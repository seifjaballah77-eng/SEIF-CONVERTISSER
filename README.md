# SEIF CONVERTISSER

واجهة تنزيل ومعالجة وسائط عربية بأسلوب بسيط: الصق الرابط، يكتشف النظام المنصة ونوع الوسائط، ثم ابدأ التنزيل مباشرة.

## Frontend
- `index.html` — واجهة عربية RTL.
- `styles.css` — تصميم داكن متجاوب.
- `app.js` — اكتشاف المنصة عند لصق الرابط، فحص الوسائط، اختيار الجودة، بدء التنزيل، وسجل محلي لمدة 30 يوماً.

## Backend
خادم Node.js مع FFmpeg وyt-dlp. ملف Docker يثبت الأدوات المطلوبة.

### API
- `GET /health` — فحص الخدمة.
- `POST /api/media/inspect` مع JSON `{"url":"https://..." }` — اكتشاف عنوان المحتوى والمنصة والنوع والجودات.
- `GET /api/media/download?url=...&quality=best` — تنزيل مباشر مع اسم ملف قابل للتنزيل.
- `POST /api/process/trim` — قص ملف.
- `POST /api/process/audio` — استخراج صوت.
- `POST /api/process/convert` — تحويل.
- `POST /api/process/compress` — ضغط.
- `POST /api/process/gif` — إنشاء GIF.

خيارات جودة التنزيل: `best`, `2160`, `1440`, `1080`, `720`, `480`, `360`, و`audio` لاستخراج MP3 عندما يكون المصدر فيديو.

## النشر
1. انشر الواجهة من GitHub Pages: Settings → Pages → Deploy from a branch → `main` → `/(root)`.
2. انشر خدمة Render باستخدام `render.yaml` الموجود في المستودع.
3. في إعدادات خدمة Render عيّن `ALLOWED_ORIGINS` إلى أصل موقع GitHub Pages، مثال: `https://seifjaballah77-eng.github.io`.
4. بعد النشر انسخ رابط خدمة Render، وافتح إعدادات SEIF CONVERTISSER والصقه في حقل Backend URL ثم احفظ.

## حدود مهمة
- الاكتشاف والتنزيل يتطلبان اتصال الخادم؛ الواجهة وحدها على GitHub Pages لا تستطيع تشغيل yt-dlp أو FFmpeg.
- لا يتم تجاوز DRM أو تسجيل الدخول أو القيود التقنية. قد ترفض المنصة بعض الروابط أو تتغير آلية الوصول لديها.
- استخدم الخدمة فقط للمحتوى الذي تملكه أو لديك إذن بتنزيله، مع الالتزام بشروط المنصة وحقوق النشر.
- دعم الصور والمنشورات يعتمد على قدرة مستخرج المنصة على إتاحة الملف الأصلي؛ لا يتم الادعاء بإمكانية تنزيل كل منشور.
- البحث بالكلمات المفتاحية عبر المنصات ما زال يحتاج موصلات بحث مستقلة؛ لا توجد نتائج بحث وهمية في الواجهة.
- سجل الروابط محلي لمدة 30 يوماً ولا يحفظ ملفات الوسائط.


### YouTube: إعداد Cookies اختيارياً
قد يرفض YouTube طلبات الخادم برسالة `Sign in to confirm you’re not a bot`. عند حدوث ذلك، يمكن للخادم استخدام ملف Cookies بصيغة Netscape من جلسة حساب تملكها:

1. من متصفحك، سجّل الدخول إلى حسابك الشخصي على YouTube وصدّر Cookies الخاصة بـ YouTube إلى ملف نصي بصيغة Netscape باستخدام أداة موثوقة تعمل محلياً. لا ترفع الملف إلى GitHub ولا ترسله لأي شخص.
2. على Windows PowerShell، حوّل الملف إلى Base64:
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("$PWD\cookies.txt"))
   ```
3. في Render → خدمة SEIF CONVERTISSER → Environment، أضف متغيراً سرياً اسمه `YT_COOKIES_BASE64`، وضع ناتج الأمر كقيمته، ثم احفظ وأعد النشر.
4. اختبر رابطاً عاماً تملك حق تنزيله. إذا استمر الرفض، فقد تتطلب المنصة تحققاً إضافياً أو قد تكون الجلسة غير صالحة.

الخادم يقرأ هذا المتغير اختيارياً ويكتب الملف مؤقتاً بصلاحيات مقيدة. لا تضع قيمة Cookies في إعدادات الواجهة أو مستودع GitHub أو سجلات الدعم. تعامل معها ككلمة مرور؛ أزل المتغير من Render وسجّل الخروج/ألغِ الجلسة إذا شككت في تسربها. استخدام Cookies لا يضمن قبول YouTube لكل طلب ولا يتجاوز DRM أو قيود المحتوى.
